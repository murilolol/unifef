Motivação

Por que os dados ficam separados?

Em um banco relacional, as informações são distribuídas em tabelas para evitar repetição e manter a organização.

Clientes

Nome, cidade, estado e outras informações cadastrais.

Pedidos

Data, status e o identificador do cliente responsável.

Produtos

Descrição, preço e categoria do item vendido.

Guardar tudo em uma única tabela causaria repetição, inconsistência e dificuldade de manutenção.
Conceito

O que é um JOIN?

Um JOIN combina linhas de duas ou mais tabelas utilizando uma condição de relacionamento.

clientes

id_cliente
nome
cidade

⇄

pedidos

id_pedido
data_pedido
id_cliente

Condição: clientes.id_cliente = pedidos.id_cliente
Chaves

Chave primária e chave estrangeira

PRIMARY KEY

Identifica cada registro de forma única.

id_cliente SERIAL PRIMARY KEY

FOREIGN KEY

Cria uma referência para outra tabela.

id_cliente INTEGER REFERENCES
clientes(id_cliente)
A chave estrangeira impede, por exemplo, o cadastro de um pedido para um cliente inexistente.

Preparação

Criação das tabelas principais

CREATE TABLE clientes (
  id_cliente SERIAL PRIMARY KEY,
  nome VARCHAR(100) NOT NULL,
  cidade VARCHAR(100),
  estado CHAR(2)
);

CREATE TABLE pedidos (
  id_pedido SERIAL PRIMARY KEY,
  data_pedido DATE NOT NULL,
  status VARCHAR(30) NOT NULL,
  id_cliente INTEGER REFERENCES clientes(id_cliente)
);
A coluna id_cliente aparece nas duas tabelas e permite estabelecer o relacionamento.
INNER JOIN

Somente registros correspondentes

O INNER JOIN retorna apenas as linhas que possuem correspondência nas duas tabelas.

SELECT
  p.id_pedido,
  p.data_pedido,
  p.status,
  c.nome AS cliente
FROM pedidos p
INNER JOIN clientes c
  ON p.id_cliente = c.id_cliente;
Leitura: para cada pedido, procure o cliente cujo identificador seja igual ao identificador armazenado no pedido.
INNER JOIN

Como o PostgreSQL interpreta

1

Lê um pedido

Obtém o valor de pedidos.id_cliente.

2

Busca o cliente

Procura o mesmo valor em clientes.id_cliente.

3

Combina as linhas

Quando encontra correspondência, reúne as colunas solicitadas.

4

Descarta o que não combina

Sem correspondência, a linha não aparece no resultado.

Aliases

Apelidos deixam a consulta mais legível

SELECT
  p.id_pedido AS codigo,
  p.data_pedido AS data,
  c.nome AS cliente
FROM pedidos AS p
INNER JOIN clientes AS c
  ON p.id_cliente = c.id_cliente;

p

Representa a tabela pedidos.

c

Representa a tabela clientes.

Em consultas grandes, aliases reduzem repetição e evitam ambiguidades.
LEFT JOIN

Todos da esquerda, correspondentes da direita

SELECT
  c.nome,
  p.id_pedido,
  p.status
FROM clientes c
LEFT JOIN pedidos p
  ON c.id_cliente = p.id_cliente;

Todos os clientes aparecem. Quando não há pedido, as colunas da tabela pedidos recebem NULL.

É o JOIN mais utilizado para relatórios que precisam preservar todos os registros de uma tabela principal.
LEFT JOIN

Encontrando clientes sem pedidos

SELECT
  c.id_cliente,
  c.nome
FROM clientes c
LEFT JOIN pedidos p
  ON c.id_cliente = p.id_cliente
WHERE p.id_pedido IS NULL;
Lógica: o LEFT JOIN mantém o cliente; se nenhum pedido for encontrado, p.id_pedido fica NULL; o WHERE mantém apenas esses casos.
NULL

Substituindo NULL com COALESCE

SELECT
  pr.nome_produto,
  pr.preco,
  COALESCE(ca.nome_categoria, 'Sem categoria') AS categoria
FROM produtos pr
LEFT JOIN categorias ca
  ON pr.id_categoria = ca.id_categoria;

Sem COALESCE

Webcam → NULL

Com COALESCE

Webcam → Sem categoria

RIGHT JOIN

Todos da direita

SELECT
  p.id_pedido,
  c.id_cliente,
  c.nome
FROM pedidos p
RIGHT JOIN clientes c
  ON p.id_cliente = c.id_cliente;
O RIGHT JOIN é válido, mas geralmente pode ser reescrito como LEFT JOIN invertendo a ordem das tabelas.
-- Forma normalmente preferida
FROM clientes c
LEFT JOIN pedidos p
  ON c.id_cliente = p.id_cliente;
FULL OUTER JOIN

Todos os registros das duas tabelas

SELECT
  c.id_cliente,
  c.nome,
  p.id_pedido,
  p.status
FROM clientes c
FULL OUTER JOIN pedidos p
  ON c.id_cliente = p.id_cliente;

Inclui

Correspondências, clientes sem pedidos e pedidos sem cliente correspondente.

Aplicações

Auditoria, comparação de bases e identificação de inconsistências.

CROSS JOIN

Todas as combinações possíveis

SELECT
  c.nome,
  ca.nome_categoria
FROM clientes c
CROSS JOIN categorias ca;
5 clientes × 4 categorias = 20 linhas
Atenção: duas tabelas com 1.000 linhas produzem 1.000.000 de combinações.
SELF JOIN

Uma tabela relacionada com ela mesma

Útil quando um registro aponta para outro registro da mesma tabela, como funcionário e supervisor.

SELECT
  f.nome AS funcionario,
  f.cargo,
  COALESCE(s.nome, 'Sem supervisor') AS supervisor
FROM funcionarios f
LEFT JOIN funcionarios s
  ON f.id_supervisor = s.id_funcionario;
Os aliases f e s representam papéis diferentes da mesma tabela.
Múltiplas tabelas

JOIN com quatro tabelas

SELECT
  p.id_pedido,
  c.nome AS cliente,
  pr.nome_produto,
  ip.quantidade,
  ip.preco_unitario
FROM pedidos p
INNER JOIN clientes c
  ON p.id_cliente = c.id_cliente
INNER JOIN itens_pedido ip
  ON p.id_pedido = ip.id_pedido
INNER JOIN produtos pr
  ON ip.id_produto = pr.id_produto;
Cada JOIN adiciona uma nova fonte de dados ao resultado.
Cálculos

Subtotal de cada item

SELECT
  p.id_pedido,
  c.nome AS cliente,
  pr.nome_produto,
  ip.quantidade,
  ip.preco_unitario,
  ip.quantidade * ip.preco_unitario AS subtotal
FROM pedidos p
JOIN clientes c ON p.id_cliente = c.id_cliente
JOIN itens_pedido ip ON p.id_pedido = ip.id_pedido
JOIN produtos pr ON ip.id_produto = pr.id_produto;
2 unidades × R$ 80,00 = R$ 160,00
Filtros

JOIN combinado com WHERE

SELECT
  p.id_pedido,
  p.data_pedido,
  c.nome AS cliente
FROM pedidos p
INNER JOIN clientes c
  ON p.id_cliente = c.id_cliente
WHERE p.status = 'Pago'
ORDER BY p.data_pedido DESC;

WHERE

Filtra as linhas após a junção.

ORDER BY

Define a ordem de apresentação.

Agregações

Quantidade de pedidos por cliente

SELECT
  c.id_cliente,
  c.nome,
  COUNT(p.id_pedido) AS quantidade_pedidos
FROM clientes c
LEFT JOIN pedidos p
  ON c.id_cliente = p.id_cliente
GROUP BY c.id_cliente, c.nome
ORDER BY quantidade_pedidos DESC;
Com LEFT JOIN, clientes sem pedidos continuam aparecendo e recebem contagem igual a zero.
Agregações

Valor total de cada pedido

SELECT
  p.id_pedido,
  c.nome AS cliente,
  SUM(ip.quantidade * ip.preco_unitario) AS valor_total
FROM pedidos p
JOIN clientes c
  ON p.id_cliente = c.id_cliente
JOIN itens_pedido ip
  ON p.id_pedido = ip.id_pedido
GROUP BY p.id_pedido, c.nome;
Tudo que aparece no SELECT e não está dentro de uma função de agregação deve ser considerado no GROUP BY.
Ponto crítico

Condição no ON ou no WHERE?

Filtro no WHERE

LEFT JOIN pedidos p
  ON c.id_cliente = p.id_cliente
WHERE p.status = 'Pago';

Pode eliminar clientes sem pedidos e aproximar o resultado de um INNER JOIN.

Filtro no ON

LEFT JOIN pedidos p
  ON c.id_cliente = p.id_cliente
 AND p.status = 'Pago';

Mantém todos os clientes e relaciona apenas pedidos pagos.

PostgreSQL

USING e NATURAL JOIN

USING

SELECT p.id_pedido, c.nome
FROM pedidos p
JOIN clientes c
USING (id_cliente);

Útil quando a coluna possui exatamente o mesmo nome nas duas tabelas.

NATURAL JOIN

SELECT *
FROM pedidos
NATURAL JOIN clientes;

Relaciona automaticamente colunas de mesmo nome. Seu uso não é recomendado em sistemas reais.

Prefira condições explícitas com ON para tornar a consulta previsível e fácil de manter.
Erros comuns

Produto cartesiano acidental

-- Consulta problemática
SELECT *
FROM clientes, pedidos;

Cada cliente será combinado com cada pedido.

-- Forma correta
SELECT *
FROM clientes c
JOIN pedidos p
  ON c.id_cliente = p.id_cliente;
Nunca omita a condição de relacionamento quando o objetivo não for gerar todas as combinações.
Erros comuns

Colunas erradas, ambíguas e SELECT *

Colunas erradas

Relacionar id_cliente com id_pedido mistura conceitos diferentes.

Ambiguidade

Quando o nome existe em mais de uma tabela, use o alias: c.id_cliente.

SELECT *

Retorna dados desnecessários, repete colunas e dificulta a manutenção.

Boa prática: selecione somente as colunas necessárias e use aliases claros.
