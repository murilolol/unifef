Introdução

O que é uma subconsulta?

Uma subconsulta, também chamada de subselect ou subquery, é uma instrução SELECT escrita dentro de outra instrução SQL.

SELECT nome_produto, preco
FROM produtos
WHERE preco > (
  SELECT AVG(preco)
  FROM produtos
);
Leitura: exibir os produtos cujo preço seja maior que a média de preços de todos os produtos.
Estrutura

Consulta interna e consulta externa

Subconsulta

É executada para produzir um valor ou conjunto de valores intermediários.

(SELECT AVG(preco)
 FROM produtos)

Consulta externa

Utiliza o resultado produzido pela subconsulta.

SELECT nome_produto, preco
FROM produtos
WHERE preco > resultado;
A subconsulta normalmente é colocada entre parênteses para separar claramente os dois níveis da instrução.

Subconsulta escalar

Quando o resultado é um único valor

Uma subconsulta escalar deve retornar exatamente uma linha e uma coluna.

SELECT nome_produto, preco
FROM produtos
WHERE preco > (
  SELECT AVG(preco)
  FROM produtos
);

Subconsulta

Calcula um único valor: a média dos preços.

Consulta externa

Compara cada produto com essa média.

Subconsulta escalar

Produto mais caro

SELECT id_produto, nome_produto, preco
FROM produtos
WHERE preco = (
  SELECT MAX(preco)
  FROM produtos
);
Importante: essa forma retorna todos os produtos empatados no maior preço. Uma consulta com ORDER BY ... LIMIT 1 retornaria somente uma linha.
Subconsulta no SELECT

Criando uma coluna calculada

Uma subconsulta escalar também pode aparecer na lista de colunas do SELECT.

SELECT
  nome_produto,
  preco,
  (SELECT AVG(preco) FROM produtos)
    AS media_geral
FROM produtos;
A média será repetida em todas as linhas porque a subconsulta não depende do produto atual.
Comparação

Diferença entre o preço e a média

SELECT
  nome_produto,
  preco,
  preco - (
    SELECT AVG(preco)
    FROM produtos
  ) AS diferenca_media
FROM produtos
ORDER BY diferenca_media DESC;

Valores positivos indicam produtos acima da média; valores negativos indicam produtos abaixo da média.

IN

Subconsulta retornando várias linhas

O operador IN verifica se um valor pertence ao conjunto retornado pela subconsulta.

SELECT nome, cidade
FROM clientes
WHERE id_cliente IN (
  SELECT id_cliente
  FROM pedidos
);
Resultado: clientes que possuem pelo menos um pedido.
IN

Filtrando por categorias

SELECT nome_produto, preco
FROM produtos
WHERE id_categoria IN (
  SELECT id_categoria
  FROM categorias
  WHERE nome_categoria IN
        ('Informática', 'Acessórios')
);

A subconsulta localiza os identificadores das categorias; a consulta externa busca os produtos associados a eles.

NOT IN

Localizando registros fora do conjunto

SELECT nome
FROM clientes
WHERE id_cliente NOT IN (
  SELECT id_cliente
  FROM pedidos
);
Cuidado com NULL: se a subconsulta retornar algum valor nulo, o resultado de NOT IN pode se tornar desconhecido e nenhuma linha ser retornada.
NOT IN e NULL

Forma mais segura

Quando houver possibilidade de valores nulos, filtre-os explicitamente ou utilize NOT EXISTS.

SELECT nome
FROM clientes
WHERE id_cliente NOT IN (
  SELECT id_cliente
  FROM pedidos
  WHERE id_cliente IS NOT NULL
);
Em consultas de ausência, NOT EXISTS costuma expressar a intenção de forma mais segura.
EXISTS

Verificando se existe correspondência

EXISTS retorna verdadeiro quando a subconsulta encontra pelo menos uma linha.

SELECT c.id_cliente, c.nome
FROM clientes c
WHERE EXISTS (
  SELECT 1
  FROM pedidos p
  WHERE p.id_cliente = c.id_cliente
);
SELECT 1 é utilizado porque o conteúdo retornado não importa; interessa apenas saber se uma linha existe.
NOT EXISTS

Clientes sem pedidos

SELECT c.id_cliente, c.nome
FROM clientes c
WHERE NOT EXISTS (
  SELECT 1
  FROM pedidos p
  WHERE p.id_cliente = c.id_cliente
);

Para cada cliente

A subconsulta procura um pedido relacionado.

Quando não encontra

O cliente permanece no resultado externo.

ANY

Comparando com algum valor

ANY retorna verdadeiro quando a comparação é verdadeira para pelo menos um dos valores retornados.

SELECT nome_produto, preco
FROM produtos
WHERE preco > ANY (
  SELECT preco
  FROM produtos
  WHERE id_categoria = 4
);
Leitura: produtos mais caros que pelo menos um produto da categoria 4.
ALL

Comparando com todos os valores

ALL exige que a comparação seja verdadeira para todos os valores retornados.

SELECT nome_produto, preco
FROM produtos
WHERE preco > ALL (
  SELECT preco
  FROM produtos
  WHERE id_categoria = 4
);
Leitura: produtos mais caros que todos os produtos da categoria 4.
Subconsulta correlacionada

A consulta interna depende da externa

Uma subconsulta é correlacionada quando utiliza uma coluna da linha que está sendo processada pela consulta externa.

SELECT p1.nome_produto, p1.preco, p1.id_categoria
FROM produtos p1
WHERE p1.preco > (
  SELECT AVG(p2.preco)
  FROM produtos p2
  WHERE p2.id_categoria = p1.id_categoria
);
A média é recalculada para a categoria do produto que está sendo analisado.
Correlacionada

Etapas da execução

1

Seleciona um produto

A consulta externa fornece sua categoria.

2

Calcula a média da categoria

A subconsulta usa p1.id_categoria.

3

Compara o preço

O produto é mantido se estiver acima da média do próprio grupo.

4

Repete para a próxima linha

O processo continua até todos os produtos serem avaliados.

Subconsulta no FROM

Criando uma tabela derivada

Uma subconsulta no FROM funciona como uma tabela temporária disponível apenas durante a consulta.

SELECT
  resumo.id_cliente,
  resumo.total_pedidos
FROM (
  SELECT id_cliente,
         COUNT(*) AS total_pedidos
  FROM pedidos
  GROUP BY id_cliente
) AS resumo
WHERE resumo.total_pedidos > 1;
No PostgreSQL, uma subconsulta no FROM deve receber um alias.
FROM + JOIN

Combinando tabela derivada com clientes

SELECT
  c.nome,
  r.total_pedidos
FROM clientes c
JOIN (
  SELECT id_cliente,
         COUNT(*) AS total_pedidos
  FROM pedidos
  GROUP BY id_cliente
) r ON r.id_cliente = c.id_cliente
ORDER BY r.total_pedidos DESC;

Primeiro é criado um resumo por cliente; depois esse resumo é relacionado à tabela de clientes.

HAVING

Subconsulta em filtros de grupos

SELECT id_cliente, COUNT(*) AS total
FROM pedidos
GROUP BY id_cliente
HAVING COUNT(*) > (
  SELECT AVG(quantidade)
  FROM (
    SELECT COUNT(*) AS quantidade
    FROM pedidos
    GROUP BY id_cliente
  ) q
);
Resultado: clientes cuja quantidade de pedidos está acima da média de pedidos por cliente.
Subconsulta em UPDATE

Atualizando com base em outro resultado

UPDATE produtos
SET preco = preco * 1.10
WHERE id_categoria = (
  SELECT id_categoria
  FROM categorias
  WHERE nome_categoria = 'Informática'
);
Antes de executar um UPDATE, recomenda-se testar a mesma condição em um SELECT.
Subconsulta em DELETE

Removendo registros selecionados

DELETE FROM clientes c
WHERE NOT EXISTS (
  SELECT 1
  FROM pedidos p
  WHERE p.id_cliente = c.id_cliente
);
Atenção: operações de exclusão são permanentes após o commit. Utilize transações e faça uma consulta de conferência.
Subconsulta em INSERT

Copiando dados de uma consulta

INSERT INTO clientes_vip
  (id_cliente, nome, total_comprado)
SELECT
  c.id_cliente,
  c.nome,
  (
    SELECT SUM(ip.quantidade * ip.preco_unitario)
    FROM pedidos p
    JOIN itens_pedido ip ON ip.id_pedido = p.id_pedido
    WHERE p.id_cliente = c.id_cliente
  )
FROM clientes c;

O INSERT ... SELECT insere na tabela de destino os dados produzidos pela consulta.

Subconsulta ou JOIN?

Duas formas de responder perguntas semelhantes

Subconsulta

SELECT nome
FROM clientes
WHERE id_cliente IN
 (SELECT id_cliente
  FROM pedidos);

JOIN

SELECT DISTINCT c.nome
FROM clientes c
JOIN pedidos p
 ON p.id_cliente = c.id_cliente;
A escolha deve considerar clareza, necessidade das colunas e plano de execução, não apenas preferência pessoal.
CTE

Alternativa para organizar consultas

Uma expressão de tabela comum, criada com WITH, pode tornar consultas longas mais legíveis.

WITH resumo AS (
  SELECT id_cliente,
         COUNT(*) AS total_pedidos
  FROM pedidos
  GROUP BY id_cliente
)
SELECT c.nome, r.total_pedidos
FROM clientes c
JOIN resumo r
  ON r.id_cliente = c.id_cliente;
CTEs não substituem todas as subconsultas, mas ajudam a dividir uma consulta complexa em etapas nomeadas.
Erros comuns

Subconsulta escalar retornando várias linhas

-- Incorreto: a subconsulta pode retornar vários preços
SELECT nome_produto
FROM produtos
WHERE preco = (
  SELECT preco
  FROM produtos
  WHERE id_categoria = 1
);
O PostgreSQL informará que a subconsulta usada como expressão retornou mais de uma linha.

Para várias linhas, utilize IN, ANY, ALL ou reformule a lógica.

Erros comuns

Falta de correlação

-- A subconsulta não relaciona o pedido ao cliente atual
SELECT c.nome
FROM clientes c
WHERE EXISTS (
  SELECT 1
  FROM pedidos p
);

Se existir pelo menos um pedido no banco, todos os clientes serão retornados.

A condição correta é p.id_cliente = c.id_cliente.

Boas práticas

Como escrever subconsultas legíveis

Organização

  • Indentar a subconsulta
  • Usar aliases significativos
  • Selecionar somente as colunas necessárias

Segurança lógica

  • Verificar a quantidade de linhas retornadas
  • Tratar valores NULL
  • Testar UPDATE e DELETE com SELECT
Uma consulta clara é mais fácil de revisar, corrigir e otimizar.

Resolução

Produtos acima da média

SELECT nome_produto, preco
FROM produtos
WHERE preco > (
  SELECT AVG(preco)
  FROM produtos
);
A subconsulta produz a média; a consulta externa compara cada produto com esse valor.
Resolução

Pedidos acima da média de valor

SELECT t.id_pedido, t.valor_total
FROM (
  SELECT id_pedido,
         SUM(quantidade * preco_unitario) AS valor_total
  FROM itens_pedido
  GROUP BY id_pedido
) t
WHERE t.valor_total > (
  SELECT AVG(x.valor_total)
  FROM (
    SELECT SUM(quantidade * preco_unitario) AS valor_total
    FROM itens_pedido
    GROUP BY id_pedido
  ) x
);

Conclusão

Subconsultas ampliam o poder das consultas SQL

Uma subconsulta permite utilizar o resultado de uma consulta como parte da lógica de outra instrução.

Filtrar

Comparar linhas com valores calculados.

Verificar

Identificar existência ou ausência de registros.

Organizar

Criar resultados intermediários reutilizados pela consulta externa.

Dominar subconsultas permite responder perguntas que exigem médias, máximos, conjuntos, comparações por grupo e dependências entre registros.
