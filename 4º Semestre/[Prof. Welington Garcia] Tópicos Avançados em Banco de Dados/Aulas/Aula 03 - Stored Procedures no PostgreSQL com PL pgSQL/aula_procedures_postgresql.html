Stored Procedures no PostgreSQL

Introdução à programação no banco de dados com PL/pgSQL

Objetivo da aula

Compreender o conceito de procedure e aprender a criar procedimentos com parâmetros, variáveis, condições e comandos SQL.

Pré-requisitos

SELECT, INSERT, UPDATE, DELETE, JOINs, subconsultas, views e noções básicas de modelagem relacional.

A partir desta aula, o aluno começa a utilizar o PostgreSQL não apenas para consultar dados, mas também para implementar lógica procedural dentro do banco.

1. O que é uma Stored Procedure?

Uma Stored Procedure é um conjunto de instruções SQL armazenadas dentro do próprio banco de dados.

Aplicação ↓ CALL realizar_venda(...) ↓ PostgreSQL executa ├── validações ├── INSERT ├── UPDATE ├── regras de negócio └── controle da operação
Em vez de enviar vários comandos SQL separados, a aplicação pode chamar uma única procedure.

2. Por que utilizar Procedures?

Reutilização

Uma mesma lógica pode ser executada diversas vezes por diferentes aplicações.

Organização

Operações complexas podem ser centralizadas em um único procedimento.

Segurança

É possível permitir a execução de uma procedure sem liberar acesso irrestrito às tabelas.

Regras de negócio

Validações e operações relacionadas podem ser executadas dentro do banco.

3. Banco utilizado na aula

Será utilizado um pequeno banco de uma loja.

CREATE TABLE clientes (
    id_cliente SERIAL PRIMARY KEY,
    nome VARCHAR(100) NOT NULL,
    email VARCHAR(100) UNIQUE,
    ativo BOOLEAN DEFAULT TRUE
);

CREATE TABLE produtos (
    id_produto SERIAL PRIMARY KEY,
    nome VARCHAR(100) NOT NULL,
    preco NUMERIC(10,2) NOT NULL,
    estoque INTEGER NOT NULL
);

5. Estrutura básica de uma Procedure

CREATE PROCEDURE nome_da_procedure()
LANGUAGE plpgsql
AS $$
BEGIN

    -- comandos

END;
$$;

CREATE PROCEDURE

Cria o procedimento armazenado.

LANGUAGE plpgsql

Define o uso da linguagem procedural do PostgreSQL.

BEGIN / END

Delimitam o bloco de comandos.

$$

Delimita o corpo da procedure.

6. Primeira Procedure

CREATE PROCEDURE cadastrar_cliente()
LANGUAGE plpgsql
AS $$
BEGIN

    INSERT INTO clientes(nome, email)
    VALUES ('Pedro Alves', 'pedro@email.com');

END;
$$;

Essa procedure cadastra sempre o mesmo cliente.

É um exemplo propositalmente simples para mostrar primeiro a estrutura do procedimento.

7. Executando com CALL

CALL cadastrar_cliente();

Depois da execução, podemos verificar os registros:

SELECT *
FROM clientes;
Procedures são normalmente chamadas com CALL.

8. Procedure com parâmetros

Para tornar a procedure reutilizável, podemos receber valores como parâmetros.

CREATE PROCEDURE cadastrar_cliente(
    p_nome VARCHAR,
    p_email VARCHAR
)
LANGUAGE plpgsql
AS $$
BEGIN

    INSERT INTO clientes(nome, email)
    VALUES (p_nome, p_email);

END;
$$;

9. Executando uma Procedure com parâmetros

CALL cadastrar_cliente(
    'Ana Martins',
    'ana@email.com'
);
CALL cadastrar_cliente(
    'Marcos Lima',
    'marcos@email.com'
);

Agora a mesma procedure pode cadastrar diferentes clientes.

10. Convenção de nomes

Uma prática comum é utilizar prefixos para facilitar a leitura do código.

Parâmetros

p_nomep_emailp_id_produto

Variáveis

v_estoquev_precov_total

A convenção não é obrigatória, mas ajuda muito quando os nomes de colunas, parâmetros e variáveis são semelhantes.

11. Procedure com UPDATE

CREATE PROCEDURE alterar_preco(
    p_id_produto INTEGER,
    p_novo_preco NUMERIC
)
LANGUAGE plpgsql
AS $$
BEGIN

    UPDATE produtos
    SET preco = p_novo_preco
    WHERE id_produto = p_id_produto;

END;
$$;
CALL alterar_preco(1, 150.00);

12. Atualizando o estoque

CREATE PROCEDURE adicionar_estoque(
    p_id_produto INTEGER,
    p_quantidade INTEGER
)
LANGUAGE plpgsql
AS $$
BEGIN

    UPDATE produtos
    SET estoque = estoque + p_quantidade
    WHERE id_produto = p_id_produto;

END;
$$;
CALL adicionar_estoque(1, 10);

13. Utilizando DELETE

CREATE PROCEDURE excluir_cliente(
    p_id_cliente INTEGER
)
LANGUAGE plpgsql
AS $$
BEGIN

    DELETE FROM clientes
    WHERE id_cliente = p_id_cliente;

END;
$$;
CALL excluir_cliente(3);

Em sistemas reais, exclusões físicas devem ser utilizadas com cuidado.

14. Declarando variáveis

O bloco DECLARE é utilizado para declarar variáveis locais.

CREATE PROCEDURE exemplo_variavel()
LANGUAGE plpgsql
AS $$
DECLARE

    v_quantidade INTEGER;

BEGIN

    SELECT COUNT(*)
    INTO v_quantidade
    FROM produtos;

    RAISE NOTICE 'Quantidade de produtos: %',
                 v_quantidade;

END;
$$;

15. SELECT INTO

O comando SELECT INTO armazena o resultado de uma consulta em uma variável.

SELECT estoque
INTO v_estoque
FROM produtos
WHERE id_produto = 1;
coluna estoque ↓ SELECT ↓ v_estoque

16. RAISE NOTICE

Utilizado para apresentar mensagens durante a execução.

RAISE NOTICE 'Olá!';
RAISE NOTICE 'Estoque atual: %', v_estoque;

O caractere % é substituído pelo valor informado.

17. Estrutura IF

IF condição THEN

    comandos;

END IF;

Também é possível utilizar ELSE:

IF condição THEN

    comandos;

ELSE

    comandos;

END IF;

18. Validando o estoque

CREATE PROCEDURE retirar_estoque(
    p_id_produto INTEGER,
    p_quantidade INTEGER
)
LANGUAGE plpgsql
AS $$
DECLARE
    v_estoque INTEGER;
BEGIN

    SELECT estoque
    INTO v_estoque
    FROM produtos
    WHERE id_produto = p_id_produto;

    IF v_estoque >= p_quantidade THEN

        UPDATE produtos
        SET estoque = estoque - p_quantidade
        WHERE id_produto = p_id_produto;

        RAISE NOTICE 'Estoque atualizado.';

    ELSE

        RAISE NOTICE 'Estoque insuficiente.';

    END IF;

END;
$$;

19. Fluxo da validação

Receber produto e quantidade ↓ Consultar estoque atual ↓ Estoque suficiente? / \ SIM NÃO ↓ ↓ Atualizar Mostrar estoque mensagem
Aqui o banco já começa a executar uma lógica semelhante à encontrada em linguagens de programação.

20. Utilizando ELSIF

IF v_estoque = 0 THEN

    RAISE NOTICE 'Produto sem estoque.';

ELSIF v_estoque <= 5 THEN

    RAISE NOTICE 'Estoque baixo.';

ELSE

    RAISE NOTICE 'Estoque normal.';

END IF;

O ELSIF permite testar várias condições em sequência.

21. Atribuição de valores com :=

v_total := v_preco * p_quantidade;

No PL/pgSQL, o operador := é utilizado para atribuir valores a variáveis.

Java

total = preco * quantidade;

PL/pgSQL

v_total := v_preco * p_quantidade;

22. RETURNING INTO

O PostgreSQL pode retornar valores gerados por um INSERT.

INSERT INTO vendas(id_cliente, valor_total)
VALUES (p_id_cliente, v_total)
RETURNING id_venda INTO v_id_venda;

Isso é particularmente útil para capturar IDs gerados automaticamente.

23. Procedure x Function

FUNCTION

Normalmente é utilizada quando se deseja calcular ou retornar algum resultado.

SELECT calcular_total(10, 20);

PROCEDURE

É usada principalmente para executar operações e sequências de comandos.

CALL registrar_venda(1, 2, 3);
Essa diferença será aprofundada posteriormente ao estudar Functions.

24. CREATE OR REPLACE PROCEDURE

Durante o desenvolvimento, podemos alterar o corpo de uma procedure sem recriá-la manualmente.

CREATE OR REPLACE PROCEDURE adicionar_estoque(
    p_id_produto INTEGER,
    p_quantidade INTEGER
)
LANGUAGE plpgsql
AS $$
BEGIN

    UPDATE produtos
    SET estoque = estoque + p_quantidade
    WHERE id_produto = p_id_produto;

    RAISE NOTICE 'Estoque alterado.';

END;
$$;

25. RAISE EXCEPTION

RAISE EXCEPTION gera um erro e interrompe a execução.

IF p_quantidade <= 0 THEN

    RAISE EXCEPTION
    'A quantidade deve ser maior que zero.';

END IF;

NOTICE

Exibe uma mensagem.

EXCEPTION

Gera erro e interrompe a operação.

26. Validando parâmetros

CREATE OR REPLACE PROCEDURE adicionar_estoque(
    p_id_produto INTEGER,
    p_quantidade INTEGER
)
LANGUAGE plpgsql
AS $$
BEGIN

    IF p_quantidade <= 0 THEN

        RAISE EXCEPTION
        'Quantidade inválida.';

    END IF;

    UPDATE produtos
    SET estoque = estoque + p_quantidade
    WHERE id_produto = p_id_produto;

END;
$$;

27. Exemplo completo: verificar estoque

CREATE PROCEDURE verificar_estoque(
    p_id_produto INTEGER
)
LANGUAGE plpgsql
AS $$
DECLARE
    v_estoque INTEGER;
BEGIN

    SELECT estoque
    INTO v_estoque
    FROM produtos
    WHERE id_produto = p_id_produto;

    IF v_estoque = 0 THEN
        RAISE NOTICE 'SEM ESTOQUE';
    ELSIF v_estoque <= 5 THEN
        RAISE NOTICE 'ESTOQUE BAIXO';
    ELSE
        RAISE NOTICE 'ESTOQUE NORMAL';
    END IF;

END;
$$;

28. Exemplo aplicado: transferência

CREATE TABLE contas (
    id_conta SERIAL PRIMARY KEY,
    titular VARCHAR(100),
    saldo NUMERIC(10,2)
);
INSERT INTO contas(titular, saldo)
VALUES
('Carlos', 2000),
('Maria', 1000);

Uma transferência exige que duas alterações relacionadas sejam realizadas corretamente.

29. Procedure de transferência

CREATE PROCEDURE transferir(
    p_origem INTEGER,
    p_destino INTEGER,
    p_valor NUMERIC
)
LANGUAGE plpgsql
AS $$
DECLARE
    v_saldo NUMERIC;
BEGIN

    SELECT saldo
    INTO v_saldo
    FROM contas
    WHERE id_conta = p_origem;

    IF v_saldo < p_valor THEN
        RAISE EXCEPTION 'Saldo insuficiente.';
    END IF;

    UPDATE contas
    SET saldo = saldo - p_valor
    WHERE id_conta = p_origem;

    UPDATE contas
    SET saldo = saldo + p_valor
    WHERE id_conta = p_destino;

END;
$$;

30. Procedures e regras de negócio

Podemos utilizar procedures para garantir regras relacionadas à consistência das operações.

IF p_quantidade <= 0 THEN
    RAISE EXCEPTION 'Quantidade inválida.';
END IF;

IF v_estoque < p_quantidade THEN
    RAISE EXCEPTION 'Estoque insuficiente.';
END IF;
Isso ajuda a evitar que dados inválidos sejam gravados mesmo quando diferentes aplicações acessam o mesmo banco.

31. Boas práticas iniciais

  • Utilizar nomes claros e descritivos.
  • Padronizar nomes de parâmetros e variáveis.
  • Validar entradas antes de alterar os dados.
  • Evitar procedures excessivamente grandes.
  • Usar RAISE EXCEPTION para situações realmente inválidas.
  • Testar cada procedure isoladamente.

32. Exercício 1

Crie uma procedure chamada:

cadastrar_produto

Ela deverá receber:

  • nome;
  • preço;
  • quantidade em estoque.

Depois, execute a procedure e verifique o resultado com SELECT.

33. Exercício 2

Crie uma procedure chamada:

alterar_email_cliente

Ela deverá receber:

  • ID do cliente;
  • novo endereço de e-mail.

34. Exercício 3

Crie a procedure:

reduzir_preco

Ela deverá receber o ID do produto e o percentual de desconto.

CALL reduzir_preco(1, 10);

Se o produto custar R$ 100,00, deverá passar a custar R$ 90,00.

35. Exercício 4

Crie uma procedure chamada:

repor_estoque

Ela deverá:

  • receber o ID do produto;
  • receber uma quantidade;
  • somar a quantidade ao estoque atual;
  • não permitir quantidade menor ou igual a zero.

36. Exercício 5

Crie uma procedure:

aplicar_desconto

Regras:

  • receber ID do produto e percentual;
  • o percentual deve ser maior que zero;
  • o desconto não pode ultrapassar 50%;
  • utilizar RAISE EXCEPTION em caso de valor inválido.

37. Desafio

Crie uma procedure chamada realizar_venda.

Ela deverá:

  • receber cliente, produto e quantidade;
  • validar se a quantidade é positiva;
  • verificar se há estoque;
  • calcular o total da venda;
  • diminuir o estoque;
  • apresentar uma mensagem de sucesso.

38. Resumo

Procedures permitem transformar o PostgreSQL em um ambiente capaz de executar regras e operações complexas diretamente no banco de dados.
