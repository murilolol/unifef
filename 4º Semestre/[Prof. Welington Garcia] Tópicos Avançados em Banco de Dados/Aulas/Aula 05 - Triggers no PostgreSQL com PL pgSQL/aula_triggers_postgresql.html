Triggers no PostgreSQL

Gatilhos, automação, validação e auditoria com PL/pgSQL

Objetivo

Entender como o banco pode reagir automaticamente a eventos como INSERT, UPDATE e DELETE.

Pré-requisitos

INSERT, UPDATE, DELETE, funções básicas em PL/pgSQL e noções iniciais de Procedures.

Trigger é um dos recursos que mais evidencia que o banco de dados também pode executar lógica automaticamente.

1. O que é uma Trigger?

Uma Trigger é um gatilho executado automaticamente quando determinado evento ocorre no banco.

Usuário executa uma operação ↓ INSERT / UPDATE / DELETE ↓ Trigger é acionada ↓ Uma função é executada automaticamente
Diferente de uma Procedure, a Trigger não precisa ser chamada manualmente com CALL.

2. Exemplo do cotidiano

Imagine um sistema em que toda alteração de preço deve ser registrada.

UPDATE no preço ↓ Produto é alterado ↓ Trigger é executada ↓ Preço antigo e novo são gravados ↓ Histórico disponível para auditoria

3. Procedure x Trigger

Procedure

É chamada explicitamente.

CALL atualizar_estoque(1, 10);

Trigger

É executada automaticamente.

UPDATE produtos
SET preco = 150
WHERE id_produto = 1;

O UPDATE pode disparar uma Trigger sem que o usuário a chame.

4. Eventos que podem disparar Triggers

INSERT

Novo registro inserido.

UPDATE

Registro existente alterado.

DELETE

Registro removido.

Uma mesma Trigger pode responder a um ou mais desses eventos.

5. Momento de execução

BEFORE

Executa antes da operação.

AFTER

Executa depois da operação.

INSTEAD OF

Executa no lugar da operação, principalmente em Views.

6. BEFORE

Comando SQL ↓ BEFORE Trigger ↓ Validação / alteração de NEW ↓ Operação é executada

Casos comuns:

  • validar dados;
  • padronizar valores;
  • impedir operações;
  • ajustar campos automaticamente.

7. AFTER

Comando SQL ↓ Operação concluída ↓ AFTER Trigger ↓ Histórico / auditoria / log

Casos comuns:

  • auditoria;
  • histórico;
  • registro de movimentações;
  • logs de operações.

9. Como uma Trigger funciona no PostgreSQL?

No PostgreSQL, normalmente criamos dois objetos:

1. Função da Trigger ↓ 2. Trigger associada à tabela ↓ Evento ocorre ↓ Trigger chama a função

10. Estrutura da função da Trigger

CREATE OR REPLACE FUNCTION nome_funcao()
RETURNS TRIGGER
LANGUAGE plpgsql
AS $$
BEGIN

    -- comandos

    RETURN NEW;

END;
$$;
O trecho RETURNS TRIGGER indica que essa função foi criada para ser executada por uma Trigger.

11. Estrutura da Trigger

CREATE TRIGGER nome_trigger
BEFORE INSERT
ON nome_tabela
FOR EACH ROW
EXECUTE FUNCTION nome_funcao();

Observe que a Trigger define:

momentoeventotabelanívelfunção

12. FOR EACH ROW

Executa a Trigger uma vez para cada linha afetada.

UPDATE produtos
SET preco = preco * 1.10;
Se 100 produtos forem alterados: FOR EACH ROW ↓ Trigger executada 100 vezes

13. FOR EACH STATEMENT

Executa a Trigger uma vez para o comando inteiro.

UPDATE produtos
SET preco = preco * 1.10;
Mesmo que 100 produtos sejam alterados: FOR EACH STATEMENT ↓ Trigger executada 1 vez

14. OLD e NEW

Triggers de linha possuem duas referências muito importantes:

NEW

Representa os dados novos.

NEW.nome
NEW.preco
NEW.estoque

OLD

Representa os dados anteriores.

OLD.nome
OLD.preco
OLD.estoque

15. OLD e NEW no INSERT

INSERT NEW → existe OLD → não existe
INSERT INTO produtos(nome, preco, estoque)
VALUES ('Webcam', 300, 10);

Dentro da Trigger:

NEW.nome    -- Webcam
NEW.preco   -- 300
NEW.estoque -- 10

16. OLD e NEW no UPDATE

UPDATE OLD → valor anterior NEW → valor novo
UPDATE produtos
SET preco = 150
WHERE id_produto = 1;

Supondo que o preço anterior fosse 120:

OLD.preco = 120
NEW.preco = 150

17. OLD e NEW no DELETE

DELETE OLD → existe NEW → não existe
DELETE FROM produtos
WHERE id_produto = 2;

Dentro da Trigger podemos acessar os dados excluídos por meio de OLD.

18. Primeira Trigger

Vamos exibir uma mensagem sempre que um produto for cadastrado.

CREATE OR REPLACE FUNCTION avisar_novo_produto()
RETURNS TRIGGER
LANGUAGE plpgsql
AS $$
BEGIN
    RAISE NOTICE
    'Novo produto cadastrado: %',
    NEW.nome;

    RETURN NEW;
END;
$$;

19. Criando o gatilho

CREATE TRIGGER trg_novo_produto
AFTER INSERT
ON produtos
FOR EACH ROW
EXECUTE FUNCTION avisar_novo_produto();

Agora a função será executada automaticamente após cada INSERT em produtos.

20. Testando

INSERT INTO produtos(nome, preco, estoque)
VALUES ('Webcam', 350, 10);

Resultado esperado:

NOTICE:
Novo produto cadastrado: Webcam

Nenhum CALL foi necessário.

21. Trigger para validação

Vamos impedir preço negativo.

CREATE OR REPLACE FUNCTION validar_preco()
RETURNS TRIGGER
LANGUAGE plpgsql
AS $$
BEGIN
    IF NEW.preco < 0 THEN
        RAISE EXCEPTION
        'O preço não pode ser negativo.';
    END IF;

    RETURN NEW;
END;
$$;

22. Trigger BEFORE INSERT OR UPDATE

CREATE TRIGGER trg_validar_preco
BEFORE INSERT OR UPDATE
ON produtos
FOR EACH ROW
EXECUTE FUNCTION validar_preco();
A mesma Trigger será executada antes de INSERT ou UPDATE.

23. Testando a validação

INSERT INTO produtos(nome, preco, estoque)
VALUES ('Produto Teste', -100, 5);

Resultado:

ERROR:
O preço não pode ser negativo.

O registro não será gravado.

24. Validando preço e estoque

CREATE OR REPLACE FUNCTION validar_produto()
RETURNS TRIGGER
LANGUAGE plpgsql
AS $$
BEGIN
    IF NEW.preco < 0 THEN
        RAISE EXCEPTION 'Preço inválido.';
    END IF;

    IF NEW.estoque < 0 THEN
        RAISE EXCEPTION
        'Estoque não pode ser negativo.';
    END IF;

    RETURN NEW;
END;
$$;

25. Alterando valores automaticamente

Podemos padronizar o nome dos produtos para letras maiúsculas.

CREATE OR REPLACE FUNCTION padronizar_nome()
RETURNS TRIGGER
LANGUAGE plpgsql
AS $$
BEGIN
    NEW.nome := UPPER(NEW.nome);
    RETURN NEW;
END;
$$;

26. Trigger de padronização

CREATE TRIGGER trg_padronizar_nome
BEFORE INSERT OR UPDATE
ON produtos
FOR EACH ROW
EXECUTE FUNCTION padronizar_nome();
INSERT INTO produtos(nome, preco, estoque)
VALUES ('mouse gamer', 250, 10);

Valor armazenado:

MOUSE GAMER

27. Por que BEFORE nesse caso?

INSERT ↓ BEFORE Trigger ↓ NEW.nome := UPPER(NEW.nome) ↓ Registro é salvo já modificado
BEFORE é especialmente útil quando queremos modificar NEW antes da gravação.

28. Auditoria

Um dos usos mais importantes de Trigger é a auditoria.

Podemos registrar:

  • qual registro foi alterado;
  • valor antigo;
  • valor novo;
  • data da alteração;
  • tipo de operação.

29. Tabela de auditoria

CREATE TABLE auditoria_produtos (
    id_auditoria SERIAL PRIMARY KEY,
    id_produto INTEGER,
    nome_produto VARCHAR(100),
    preco_antigo NUMERIC(10,2),
    preco_novo NUMERIC(10,2),
    data_alteracao TIMESTAMP
        DEFAULT CURRENT_TIMESTAMP
);

30. Função de auditoria

CREATE OR REPLACE FUNCTION auditar_preco_produto()
RETURNS TRIGGER
LANGUAGE plpgsql
AS $$
BEGIN
    INSERT INTO auditoria_produtos(
        id_produto,
        nome_produto,
        preco_antigo,
        preco_novo
    )
    VALUES(
        OLD.id_produto,
        OLD.nome,
        OLD.preco,
        NEW.preco
    );

    RETURN NEW;
END;
$$;

31. Trigger de auditoria

CREATE TRIGGER trg_auditar_preco
AFTER UPDATE OF preco
ON produtos
FOR EACH ROW
EXECUTE FUNCTION auditar_preco_produto();
UPDATE OF preco relaciona a Trigger a comandos UPDATE que mencionam a coluna preço.

32. Testando a auditoria

UPDATE produtos
SET preco = 160
WHERE id_produto = 1;

Depois:

SELECT *
FROM auditoria_produtos;

O histórico mostrará o preço anterior e o novo preço.

33. Fluxo da auditoria

UPDATE produtos ↓ Registro alterado ↓ AFTER UPDATE ↓ trg_auditar_preco ↓ auditar_preco_produto() ↓ INSERT auditoria_produtos

34. Histórico de exclusões

CREATE TABLE produtos_excluidos (
    id_historico SERIAL PRIMARY KEY,
    id_produto INTEGER,
    nome VARCHAR(100),
    preco NUMERIC(10,2),
    estoque INTEGER,
    data_exclusao TIMESTAMP
        DEFAULT CURRENT_TIMESTAMP
);

35. Função para registrar DELETE

CREATE OR REPLACE FUNCTION registrar_produto_excluido()
RETURNS TRIGGER
LANGUAGE plpgsql
AS $$
BEGIN
    INSERT INTO produtos_excluidos(
        id_produto,
        nome,
        preco,
        estoque
    )
    VALUES(
        OLD.id_produto,
        OLD.nome,
        OLD.preco,
        OLD.estoque
    );

    RETURN OLD;
END;
$$;

36. Trigger BEFORE DELETE

CREATE TRIGGER trg_produto_excluido
BEFORE DELETE
ON produtos
FOR EACH ROW
EXECUTE FUNCTION registrar_produto_excluido();
DELETE FROM produtos
WHERE id_produto = 2;

Os dados do produto são registrados antes da exclusão.

37. OLD e NEW — resumo

INSERT

NEW: sim

OLD: não

UPDATE

NEW: sim

OLD: sim

DELETE

NEW: não

OLD: sim

Essa tabela é uma das informações mais importantes de toda a aula.

38. TG_OP

O PostgreSQL disponibiliza uma variável especial:

TG_OP

Ela informa qual operação disparou a Trigger:

INSERTUPDATEDELETE

39. Exemplo com TG_OP

CREATE OR REPLACE FUNCTION verificar_operacao()
RETURNS TRIGGER
LANGUAGE plpgsql
AS $$
BEGIN
    RAISE NOTICE
    'Operação executada: %',
    TG_OP;

    IF TG_OP = 'DELETE' THEN
        RETURN OLD;
    END IF;

    RETURN NEW;
END;
$$;

40. Uma Trigger para vários eventos

CREATE TRIGGER trg_produtos_operacoes
AFTER INSERT OR UPDATE OR DELETE
ON produtos
FOR EACH ROW
EXECUTE FUNCTION verificar_operacao();

Agora uma única função pode identificar qual evento ocorreu usando TG_OP.

41. Quando utilizar Trigger?

  • auditoria;
  • histórico automático;
  • registro de movimentações;
  • padronização de valores;
  • sincronização de dados;
  • ações que devem ocorrer independentemente da aplicação.

42. Quando evitar Trigger?

UPDATE tabela A ↓ Trigger A ↓ UPDATE tabela B ↓ Trigger B ↓ UPDATE tabela C
Triggers em excesso podem deixar a lógica do sistema difícil de entender, testar e manter.

43. Trigger x Constraint

Nem toda validação precisa de Trigger.

CREATE TABLE exemplo (
    preco NUMERIC(10,2)
        CHECK (preco >= 0)
);

Para uma regra simples como preço não negativo, uma constraint pode ser mais adequada.

44. Quando usar CHECK?

Use uma constraint quando a regra for simples e declarativa.

CHECK (idade >= 18)

CHECK (preco > 0)

CHECK (estoque >= 0)
Quanto mais simples for a solução, melhor. Trigger não deve ser a primeira escolha para toda validação.

45. Trigger x Procedure x Constraint

Constraint

Regra simples sobre dados.

Procedure

Operação chamada explicitamente.

Trigger

Ação automática em resposta a evento.

46. Removendo uma Trigger

DROP TRIGGER trg_validar_preco
ON produtos;

Depois, se necessário, removemos a função:

DROP FUNCTION validar_preco();

Trigger e função são objetos diferentes.

58. O que o aluno precisa lembrar?

  • Trigger não é chamada manualmente.
  • NEW representa o novo registro.
  • OLD representa o registro anterior.
  • BEFORE ocorre antes da operação.
  • AFTER ocorre depois da operação.
  • No PostgreSQL, a Trigger normalmente executa uma função PL/pgSQL.
